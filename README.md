
# Email Phishing Detector

A Python based application for detecting common phishing  indicators in email text files.

## Features

- Upload and analyze email text files through a web interface
- Detect suspicious keywords and phrases
- Detect suspicious links, IP addresses, and lookalike domains
- Identify potentially suspicious sender domains
- Identify suspicious attachment filenames
- Calculate risk score from 0 to 100 depends on the suspicious type
- Display Low, Medium, or High risk levels
- Store scan summaries in PostgreSQL
- Display recent scan history
- Handle file validation and database connection errors

## AWS Architecture

The application is deployed on AWS using Terraform.

The infrastructure includes:
- **Amazon EC2:** Two application instances running Flask through Gunicorn.
- **Application Load Balancer:** Distributes incoming HTTP requests between the two EC2 instances and performs health checks through `/health`.
- **Amazon RDS:** A PostgreSQL database deployed in private subnets.
- **AWS Secrets Manager:** Stores the application database credentials securely.
- **Amazon S3:** Stores the application deployment package.
- **Amazon CloudWatch:** Provides infrastructure metrics, application logs, monitoring dashboards, and alarms.
- **AWS Systems Manager:** Enables administrative access to EC2 instances without SSH keys.

The application instances are deployed in separate availability zones. Security groups restrict database access to the application instances and the temporary database setup instance.

## Monitoring

The CloudWatch dashboard includes:
- CPU utilization for both EC2 instances.
- Application Load Balancer request count.
- HTTP 5xx errors generated by the load balancer and application targets.
- Number of healthy application targets.

CloudWatch also collects application error logs and EC2 setup logs.

Two CPU alarms monitor high resource utilization, and an additional alarm detects when fewer than two application instances are healthy.

## AWS Deployment with Terraform

Infrastructure is defined in the `terraform/` directory.

### Prerequisites

- Terraform installed locally.
- AWS CLI installed and configured.
- An AWS account with permissions to provision the required infrastructure.
- A PostgreSQL application user and database credentials stored in AWS Secrets Manager.
- The application deployment package generated using `create_zip.py`.

### Deployment Process

1. Generate `deploy/app.zip` by running `python create_zip.py` from the project root.
2. Initialize Terraform in the `terraform/` directory using `terraform init`.
3. Review the deployment configuration, AWS region, account settings, and required variables.
4. Provision the database and networking resources.
5. Initialize the database schema and configure the application database user's permissions.
6. Create or configure the application credentials in AWS Secrets Manager.
7. Deploy the application instances and load balancer with `enable_application=true` and the application secret ARN.
8. Verify that both EC2 instances pass the load balancer health checks.
9. Open the application using the `application_url` Terraform output.

The optional `enable_db_bootstrap` variable controls the temporary EC2 instance used for database setup. It should be disabled after initialization.

**Deployment note:** The existing environment was verified after completing initial EC2 setup manually. A fully unattended deployment from a clean environment has not yet been verified.

### Infrastructure Cleanup

Terraform-managed resources can be removed using `terraform destroy` from the Terraform directory, with the same configuration and variables used for deployment.

Review the destruction plan before confirming. Verify afterward that the application instances, load balancer, RDS instance, and other Terraform-managed resources have been removed.

Resources created manually outside Terraform, including application credentials in Secrets Manager, require separate cleanup.

## Setup

Requirements:
- Python
- PostgreSQL

1. Create a Python virtual environment:

   python -m venv .venv

2. Activate the virtual environment on Windows:

   .\.venv\Scripts\Activate.ps1

3. Install dependencies:

   python -m pip install -r requirements.txt

4. Create a PostgreSQL database named phishing_detector.

5. Execute schema.sql in that database using a database
   administrator or another role with schema creation privileges.

6. Create an application database user with permission to connect
   to the database and SELECT and INSERT into the scans table.
   Grant the required schema and identity-sequence permissions.

7. Copy .env.example to .env and fill in your database credentials.

python app.py

## Limitations

- Detection is based on predefined rules, not machine learning.
- A low score does not guarantee that an email is safe.
- Attachment analysis checks filenames, not attachment contents.
- URL analysis does not visit external websites.
- Sender spoofing detection does not perform SPF, DKIM,
  or DMARC verification.
- The built-in Flask server is intended for development,
  not production deployment.
